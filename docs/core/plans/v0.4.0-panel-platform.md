# RustCMS-Core v0.4.0: panel platform features

- Status: **revised 2026-10-17** after the maintainer's assistant and a Codex review.
  Approved for W7, W9 and W1 (contracts below); W2 onwards need another plan
  round (requirements recorded under "Review requirements").
- Date: 2026-10-17
- Driver: `rust-panel` (EasyPanel-like server panel built on RustCMS). Its domain
  plan lives in that repository. Everything here is **generic framework
  work**; nothing Docker-specific belongs in Core.
- Release: v0.4.0 (minor). Extension host API v1 scripts keep working.

## Why

Admin pages that drive something which is *not* a database row (an external
service, a process, a container) can't use any existing mechanism today.

1. `ApiRoutes` (`crates/rustcms-auth/src/http/api.rs:19`) accepts **only API-guard
   tokens**, refuses an admin session with 401, and may not sit under
   `admin_path`. The admin SPA authenticates with an `HttpOnly` session cookie
   (`guards/session.rs:400`), so its JavaScript has no bearer token.
2. Browser `WebSocket` and `EventSource` cannot set an `Authorization` header,
   so streaming endpoints *must* use the cookie session.
3. `Resource` needs a SeaORM entity. `PanelPage::data`
   (`crates/rustcms-admin/src/features/custom/page.rs`) is GET-only.
4. The only remaining option is raw `app.routes(..)` with authorization
   hand-written in each handler. Such routes are invisible to `route:list` and
   `permission:sync`.
5. `authenticate` (`guards/guard.rs:124`) checks Origin and CSRF only for unsafe
   methods. A WebSocket upgrade is a GET, so it gets **no Origin check**. With
   `SameSite=Lax` cookies, any same-site subdomain could open an authenticated
   socket (cross-site WebSocket hijacking).
6. There is no WebSocket/SSE support (the axum `ws` feature is off), no
   pub/sub, and no periodic task runner. `App::serve` (`crates/rustcms-core/src/app.rs:326`)
   starts only HTTP and queue workers.
7. Script pages can't share React or the UI kit, have no API client, and only
   get `/p/$slug` with no sub-paths (`admin-ui/src/app/router.tsx:164`).
8. The CSP is a hard-coded const (`crates/rustcms-admin/src/panel/spa.rs:27`).
   `style-src 'self'` blocks libraries that inject `<style>` (xterm.js).
9. Several more gaps:
   - Config can't read Docker secrets (`*_FILE`).
   - `Secret` encrypts only through the settings store, so models have no
     encrypted column.
   - `TestApp::new` takes a `fn` pointer, which can't capture test doubles.
   - `db_test!` always emits a SQLite test, so there is no MySQL-only mode.

## Decisions (2026-10-17)

- **Scope:**
  - **v0.4.0:** W7, W9, W1, then a hardened W2/W3, and W6 only if its spike
    passes under the current CSP.
  - **v0.4.1:** W4, W5, W8.
  - **Later:** W10.
- **Acceptance example** for v0.4.0: a v1 script page that calls an
  `AdminRoutes` POST and reads an SSE stream. No React page or scheduler is needed.
- **Security ADRs** are written before the code they govern, not at tag time.
- **W1 types:** `AdminRoutes` takes a separate `AdminAccess`, with no `Public`
  variant. An anonymous admin route cannot be written.

## Contracts for the first items

### W7 (done when): `*_FILE`
- **Names:**
  - The well-known variables (`APP_NAME`, `APP_ENV`, `APP_DEBUG`, `APP_URL`,
    `APP_KEY`, `DATABASE_URL`, `REDIS_URL`) accept `<VAR>_FILE`.
  - So does every `RUSTCMS_<PATH>_FILE`: the `_FILE` suffix is stripped from
    the last segment before mapping (`RUSTCMS_MAIL__SMTP__PASSWORD_FILE` →
    `mail.smtp.password`).
  - A last segment that is only `FILE` is an ordinary key
    (`RUSTCMS_LOG__FILE` → `log.file`).
  - A setting whose own name ends in `_file` cannot be given by environment
    (documented; use a TOML file).
- **Precedence:** a file value sits in the tier of its variable. Well-known
  variables come after files; `RUSTCMS_*` come last.
- **Errors:** the variable and its `_FILE` both set is an error. So are an
  unreadable, non-UTF-8, empty or over-64-KiB file. Errors name the variable
  and the path, never the content.
- **Parsing:**
  - One trailing `\n` or `\r\n` is removed; other whitespace is kept.
  - The value is then parsed as figment parses the environment (`true`, numbers).
- **Tests:** `figment::Jail` cases for each rule above.

### W9 (done when): testing ergonomics
- `TestApp::new` and `with_config` take `impl FnOnce(Config) -> AppBuilder`.
  Existing `fn` callers compile unchanged. Tests cover a capturing closure and
  a function item.
- `RUSTCMS_TEST_BACKENDS=sqlite,postgres,mysql` (any subset) selects the
  backends `db_test!` runs. The default (unset) is all three, unchanged.
  - An empty or unknown name fails the test.
  - A selected server backend counts as required (missing → failure, never an
    all-skipped green run).
  - A backend that is in `RUSTCMS_TEST_REQUIRE` but not selected fails.
- Guide: testing page. `AppBuilder::bind` replaces by concrete type; bind a
  newtype around `Arc<dyn Trait>` for a test double.

### W1 (done when): `AdminRoutes`
- **API:**
  - `AdminRoutes::new("/docker")` (or `scope()`), with
    `.get/.post/.put/.patch/.delete(path, AdminAccess, handler)` and `.nest()`.
  - Mounted at `{admin_path}/api/x{prefix}{path}`.
  - `list()`, `permissions()`, `register(&mut app)`.
  - `AuthProvider::admin_permissions(&routes)` declares the permissions in the
    admin guard, so `permission:sync` sees them.
- **Access:**
  - `AdminAccess::authenticated()`: any signed-in admin session.
  - `AdminAccess::can(p)`: that session's user holds `p` in the admin guard
    (super admin passes).
  - Every route states its access, nested children included. There is no
    `Public`.
  - The check runs in a route layer, before extractors read anything.
  - API tokens and JWTs are not admin credentials: 401.
  - `HEAD` follows `GET`; other undeclared methods are 405.
- **Session guard:** unchanged. Unsafe methods need the Origin check and the
  CSRF header (403 `csrf_mismatch`). A frozen or ended session is anonymous (401).
- **`register` panics on** a duplicate method and path. Collisions with
  built-in admin routes cannot happen: nothing built in lives under `api/x`,
  which `tests/paths.rs` checks. `register` also describes the routes for
  `route:list` (source `app`).
- **Responses:** private, `no-store` (admin API path). Errors use the admin
  JSON error shape.
- **Testing helper:** `rustcms_testing::admin_routes::assert_access(&app,
  &routes, cases)`. It takes explicit actors and expected statuses (anonymous
  with valid CSRF, signed in without the permission, with it, API token), so
  intent is checked independently of the declaration.
- **Tests:**
  - anonymous / token / no permission / permission;
  - malformed body refused before extraction (403, body never polled);
  - nested routes and HEAD;
  - different permissions on one path;
  - write without CSRF;
  - write from a foreign Origin;
  - frozen session;
  - `route:list`;
  - `permission:sync` sees the permissions;
  - the duplicate and collision panics.
- **ADR 0026** (admin routes) and the guide page *Admin routes*.

## Review requirements for later items (from the Codex review)

- **W2 tickets:**
  - The ticket store is atomic: a database claim or a Redis atomic consume,
    not the session blob.
  - A ticket is random and hashed, bound to the session, user, credential
    version and target route.
  - It is consumed with the current cookie and the route's access; it fails
    closed on expiry, replay, logout, rotation or a store error.
  - Tests: concurrent consume across instances, a concurrent renewal, a wrong
    target.
- **W2 Origin:**
  - The Origin check is strict and mandatory on upgrade: no `Referer`
    fallback.
  - SSE is side-effect free but still limited.
- **W2 authorization on long-lived connections:**
  - Read streams are separate from command sockets.
  - Streams have a documented bounded revocation latency, rechecking session
    expiry, activity, `auth_version` and fresh permissions through the
    resolver's generation, with a time bound.
  - Every command is authorized again when it runs.
- **W2 resource limits:**
  - frame, message, byte and write-buffer limits;
  - handshake and ticket rate limits;
  - a per-user cap, stated as per instance or as a deployment-wide lease;
  - an instance cap.
  - Capacity is reserved atomically and released on every path.
- **W2 lifecycle:**
  - Keep `TimeoutLayer` and test SSE and WS through the full stack.
  - Supervise upgraded tasks and cancel them at shutdown within a grace period.
  - Decide whether live traffic renews the session.
- **W2 SPA side:**
  - Realtime handles are bound to the session epoch, closed on unmount,
    logout, account change and rotation.
  - Each reconnect gets a new ticket, with jittered bounded backoff, and stops
    on 401 or 403.
- **W3:**
  - Authorize before subscribing; a shared producer never serves another
    principal's data.
  - Bounded keys, payload and producers.
  - Lag is surfaced as a resync event.
  - The hub is process-local.
- **W4:**
  - Globally aligned slots, claimed durably together with the enqueue (check
    the queue's receipts first).
  - State the overlap policy, crash recovery, timezone and DST, and manual
    runs. `exclusive` does not prevent overlap.
- **W5:**
  - v1 stays separate (`WIDGET_API_VERSION` 1 keeps working).
  - v2 is added alongside, with `requires { api, react }` checked before the
    script runs.
  - The splat route carries the sub-path in requests and cache keys, plus an
    admin-oracle case.
  - The SDK preset is vendored by `make:page --react`; no npm publish yet.
- **W6:**
  - Prove the terminal under the current CSP first.
  - At most, allow the same-origin WebSocket endpoint.
  - No external sources, no style-hash API, never `unsafe-*`.
  - Keep `CONTENT_SECURITY_POLICY` as the default.
- **W8:**
  - A versioned envelope with a key id.
  - Previous keys decrypt only (they never revive sessions or JWTs).
  - A resumable `key:reencrypt` that covers settings secrets too.
  - Explicit row/column context (AAD).
  - Explicit encrypt and decrypt calls, not transparent SeaORM conversion.

## Work items

### W1. `AdminRoutes`: declared, permissioned admin-session routes
- New file `crates/rustcms-auth/src/http/admin_routes.rs`, re-exported from the
  facade and prelude.
- `AdminRoutes::new("/docker")` mounts under `{admin_path}/api/x/docker/...`.
  The `x/` namespace keeps clear of the built-in admin API.
- Methods: `.get/.post/.put/.patch/.delete(path, Access, handler)`, plus
  `.sse()` and `.ws()` (W2) and `.nest()`.
- `Access` is reused. `authenticated()` means any admin session; `can(p)`
  checks with `guard == ADMIN_GUARD`. Access is checked in a route layer
  before extractors, the same way `ApiRoutes` does it.
- CSRF and Origin on writes come from the existing session guard.
- `register(&mut app)` calls `describe_routes` (so routes show in `route:list`)
  and panics on duplicates.
- `AuthProvider::admin_permissions(&routes)` is the twin of `api_permissions`
  (`provider.rs:61`), so `permission:sync` sees the permissions.
- Tests:
  - An admin session without the permission gets 403.
  - An API token gets 401.
  - A write without CSRF is rejected.
  - The routes appear in `route:list`.

### W2. Realtime: SSE and WebSocket with session auth
- Workspace `axum` gains the `ws` feature, plus `tokio-stream`.
- New file `crates/rustcms-auth/src/realtime.rs`.
  - **`AdminSocket`** wraps `WebSocketUpgrade`.
    - It needs an admin `Authenticated` and **always** calls `check_origin`
      (make it `pub(crate)`).
    - It then needs a CSRF proof. Either the subprotocol `rustcms.csrf.<token>`
      validated by `csrf_matches`, or a single-use ticket from
      `POST {admin}/api/auth/socket-ticket` (stored in the session, 30 s TTL).
    - It produces a `LiveSession { user_id, session_id, auth_version }`.
  - **Revalidation:** every `realtime.revalidate_secs` (default 60) it re-checks
    the session row, `is_active`, `auth_version` and the route permission.
    - A WebSocket closes with code 4401 or 4403.
    - An SSE stream ends.
    - This keeps a long-lived connection from outliving a logout or role change.
  - **`sse(stream)`** wraps axum `Sse` with a 15 s keep-alive and the same
    revalidation.
- Limits: `realtime.max_per_user` (default 20), an idle timeout, and ping/pong.
- `TimeoutLayer` (`http/mod.rs:213`): prove with a test that upgraded and
  streamed responses outlive `timeout_secs`. If they don't, exempt
  `.sse()`/`.ws()` routes with a marker extension.
- Graceful shutdown: a `ShutdownToken` in `AppState` closes sockets and streams,
  and `realtime.shutdown_grace_secs` bounds it.
- Tests use a real `axum::serve` on an ephemeral port with `tokio-tungstenite`:
  - A cross-origin upgrade gets 403.
  - A missing CSRF proof gets 403.
  - A logout closes the socket within the revalidation interval (1 s in tests).
  - The per-user cap is enforced.
  - SSE survives longer than `timeout_secs`.
  - Shutdown closes sockets.

### W3. `realtime::Hub<K, T>` (rustcms-core)
- A keyed registry of bounded `tokio::sync::broadcast` channels.
  - `hub.subscribe(key, || producer)` starts the producer for the first
    subscriber and aborts it when the last one leaves.
  - `hub.publish(key, value)` serves always-on producers.
  - Lagging receivers skip ahead.
- It is bound through DI.
- Tests under `tokio::time::pause` check the producer lifecycle and lag.

### W4. Scheduler (rustcms-core)
- New file `crates/rustcms-core/src/schedule.rs`, plus the `cron` crate.
- API: `AppBuilder::schedule(name, Schedule::every(d) | Schedule::cron(expr)?, |state| async {..})`.
  `Schedule::job(|| J{..})` enqueues a queue `Job` on each tick, so retries and
  history stay in the queue.
- It starts next to `Workers::start` in `serve()` on the same shutdown watch.
- Each tick runs under `jobs::exclusive(state, "schedule:<name>", ttl, ..)`.
  Ticks never overlap, and missed ticks are skipped, not caught up.
- Config: `[schedule] enabled`. Commands: `schedule:list` and `schedule:run <name>`.
- Tests:
  - Interval and cron firing.
  - No overlap.
  - Single-runner with Redis (`RUSTCMS_TEST_REDIS`).
  - Shutdown stops it.

### W5. Extension host API v2: React pages that share the SPA
- `admin-ui/src/lib/widgets.ts` and a new `admin-ui/src/lib/host.ts`. `window.rustcms` gains:
  - `apiVersion: 2`.
  - `modules`:
    - `react`, `react-dom/client`, `react/jsx-runtime` and `@tanstack/react-query`
      (the host instances).
    - `ui`: `components/ui/*`, `Page` and `PageHeader` from
      `components/layout.tsx`, `Loading` and `ErrorState` from
      `components/states.tsx`, and `cn`.
  - `registerReactPage`, `registerReactSlot` and `registerReactCell`. They render
    **inside** the host React tree, so the QueryClient, theme and i18n are
    shared.
- `PageProps` v2 has the v1 fields (`data`, `locale`, `t`, `navigate`, `reload`) plus:
  - `api`: the `api/client.ts` client, with automatic CSRF and a typed `ApiError`.
  - `path`: the sub-path after the slug.
  - `search`.
  - `realtime.socket(path, {binary})`: a same-origin `wss` URL under
    `{admin}/api/x`, with the CSRF subprotocol and reconnect with backoff.
  - `realtime.events(path)`.
  - `can(permission)`.
- Router: add the splat route `/p/$slug/$` next to `/p/$slug`.
  - Rust side: route `pages/{slug}/{*rest}`.
  - `Ctx::page_path()` gives `PanelPage::data` the sub-path.
- **App source convention:**
  - React sources live in `resources/admin/src/<vendor>/`.
  - The build writes `resources/admin/js/<vendor>/*.js`, which is embedded
    with the existing `PanelProvider::extension_script(name, include_str!(..))`
    (`panel/provider.rs:82`).
  - `rustcms make:page <Name> --react` scaffolds the Rust `PanelPage`, a TSX
    page and the Vite config. Add `resources/admin/src` to
    `crates/rustcms-cli/src/layout.rs`.
- **SDK** `admin-ui/sdk/`, published as `@rustcms/admin-sdk`:
  - v2 `.d.ts` types (also through `ts-rs`).
  - Vite preset `rustcmsExtension({ name })`:
    - Builds an IIFE.
    - Maps externals to `window.rustcms.modules.*`.
    - Emits no inline code (CSP-safe).
- Consider making the 10 s extension load deadline configurable.
- Tests:
  - vitest: v1 scripts still load; a v2 page renders with the shared
    QueryClient; the splat route passes `path`; `api` sends CSRF.
  - Playwright: an SDK-built extension loads under the real CSP with no
    violations.

### W6. Configurable CSP
- `spa.rs`: replace the `CONTENT_SECURITY_POLICY` const with a `Csp` built at boot.
  `security_headers()` reads it.
- New `PanelProvider` methods:
  - `.csp_connect_src([..])`. The `ws(s)://<app.url host>` source is added by default.
  - `.csp_style_hashes([..])`.
  - `.csp_worker_src_self()`.
- There is deliberately **no** `unsafe-inline` or `unsafe-eval` API.
- **Spike first:** does xterm.js (with `@xterm/addon-webgl` and `xterm.css`
  loaded via `extension_style`) run under the CSP? The result decides whether
  `csp_style_hashes` is enough.

### W7. Secrets from files
- `config.rs` (`Config::figment`, around line 118): every well-known variable
  (`DATABASE_URL`, `APP_KEY`, `REDIS_URL`, …) and every `RUSTCMS_*` also
  accepts `<VAR>_FILE`.
- The trimmed file content is used. Setting both is an error.

### W8. Encrypted model columns
- An `Encrypted<T: Serialize + DeserializeOwned>` SeaORM value type, stored as
  text.
  - It is AES-GCM with the APP_KEY-derived key, reusing the `settings.rs`
    secret crypto.
  - It serializes as redacted in `Debug` and in JSON.
- It needs key rotation support that matches what settings do today. If
  settings have none, document the limitation.
- Tests: round-trip, a tampered ciphertext is rejected, redaction, and all three
  DBs under `db_test!`.

### W9. Testing ergonomics
- `TestApp::new` and `with_config` accept `impl FnOnce(Config) -> AppBuilder`,
  so a closure can bind test doubles. The current `fn` pointer callers still
  compile.
- `db_test!` gets a backend selection, for example
  `RUSTCMS_TEST_BACKENDS=mysql`, that skips SQLite. Apps that run on MySQL
  only can then test only on MySQL. The default is unchanged.
- Document that `AppBuilder::bind` replaces by **concrete type**. Recommend
  binding a newtype around `Arc<dyn Trait>`.

### W10. TOTP two-factor authentication (v0.4.x)
- A `user_two_factor` migration, enrolment with QR and recovery codes, a login
  challenge step, and admin reset.
- Admin UI in `pages/account.tsx` and `pages/login.tsx`.

## Order
1. W7, W9 and W1. They are small and unblock everything else.
2. W2 and W3.
3. The W6 spike, then W5 together with W6.
4. W4 and W8.
5. Tag **v0.4.0**: release notes, guide chapters, ADRs 0026–0031 (admin routes,
   realtime, scheduler, extension host v2, configurable CSP, encrypted
   columns), and `CLAUDE.md` rules (every `.ws()`/`.sse()` route goes through
   `AdminSocket`/`sse`; no CSP loosening beyond hashes).
6. W10, released as v0.4.x.

`examples/demo` gains a reference React page that uses SSE, a scheduled task,
and an `AdminRoutes` POST.

## Out of scope
Anything about Docker, Swarm, Traefik or metrics. Those stay in `rust-panel`.
The queue already supports extra queues through `queue.queues`, so it needs
no change.
