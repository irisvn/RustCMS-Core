## 1. Đã làm

### Storage (`rustcms::storage`)
- Trait `Storage`, với hai driver:
  - **local**: dùng `cap-std`, mọi thao tác neo vào root đã mở nên không thoát ra
    ngoài được qua symlink. Ghi theo trình tự file tạm → fsync → rename → fsync
    thư mục. Lúc boot kiểm tra root ghi được.
  - **S3-compatible**: dùng `object_store`, bật bằng feature `s3`.
- Key do framework sinh (`yyyy/mm/<uuid>.<ext>`).
- `StorageProvider`, mục cấu hình `[storage]`.
- `AppBuilder::body_limit(method, path, bytes)`: giới hạn body riêng cho đúng
  một route.

### Media library (`AdminProvider::media()`)
- Resource `media`: soft delete, user chỉ thấy file của mình trừ khi có
  `media.manage_all`; route create/update chung luôn bị từ chối.
- **Upload** `POST /admin/api/media` (multipart):
  - kiểm quyền trước khi đọc body;
  - nhận diện loại file từ nội dung (magic bytes) theo danh sách cố định, và kiểm
    tra file kết thúc đúng định dạng;
  - giới hạn số pixel, số upload đồng thời, rate limit theo user, độ dài tên file;
  - hỗ trợ `Idempotency-Key`.
- **Tải file** `GET /admin/api/media/{id}/file`:
  - luôn đi qua app (không dùng presigned URL), có kiểm quyền; media đã xoá thì
    trả 404;
  - header: `nosniff` và CSP `sandbox`; chỉ ảnh mới hiển thị inline;
  - rate limit theo user.
- **An toàn khi crash:**
  - intent upload được commit trước khi lưu file, rồi bị xoá cùng transaction
    tạo bản ghi media;
  - force delete xếp job xoá file vào hàng đợi trong cùng transaction;
  - `media:prune` và worker chạy mỗi phút: dọn job, intent bị bỏ dở, file tạm.
- 3 migration framework mới; thêm hook `Resource::after_force_delete`.

### Field media và rich text
- `Field::media()` / `media_list(n)` kèm `.accept()` / `.max_size()`.
- **Bước kiểm tra cuối:** chạy sau hook, ở create, update và restore. Gồm
  `belongs_to`, media và ảnh trong rich text. Kiểm quyền xem trước, rồi mới khoá
  các dòng media được tham chiếu (`FOR SHARE`, theo thứ tự id).
- `Field::rich_text()` (cột JSON), module `rich_text`:
  - grammar đóng (node, mark, thuộc tính), có giới hạn kích thước, số mark trên
    mỗi đoạn text, độ sâu, số ảnh;
  - `to_html` xuất HTML đã escape cho headless.
- Field media và rich text không được có giá trị mặc định ở DB.

### Admin SPA (vocabulary 3)
- Transport multipart trong `ApiClient`.
- `FileUpload`:
  - upload ngay khi chọn file;
  - "Retry upload" gửi lại cùng key;
  - sắp xếp lại và xoá file khỏi danh sách;
  - chặn lưu form khi còn upload dang dở.
- `RichEditor` (TipTap 3.31.3, đã pin, `injectCSS: false`):
  - ánh xạ chặt giữa tài liệu và JSON của editor; tài liệu editor không chứa hết
    được thì hiển thị read-only, không cho sửa;
  - chèn ảnh qua media library, có retry cùng key.
- Trang xem render rich text bằng React (không chèn HTML).
- **CSP vẫn giữ nguyên.** E2E chạy editor (gõ chữ, in đậm, list, chèn ảnh) không
  có vi phạm CSP nào.

### Demo
Posts có ảnh bìa và nội dung rich text. Editor được quyền upload media.

## 2. Review Codex (4 P1, 19 P2, 4 P3) — đã xử lý

| Finding | Xử lý |
|---|---|
| Symlink bị tráo giữa lúc kiểm tra và lúc ghi (local) | Viết lại bằng `cap-std` |
| Prune xoá file của upload vừa commit | Hoàn tất upload bắt buộc xoá được intent của chính nó; prune chiếm intent trong transaction trước khi xoá file |
| Tải file vẫn phục vụ media vừa bị xoá | Truy vấn thứ hai lọc `deleted_at IS NULL` |
| Rich text với 15.000 mark làm crash trang | Tối đa 5 mark, không trùng loại |
| Lock media trước khi kiểm quyền xem | Kiểm visibility trước, chỉ lock những id user xem được |
| Grammar server lệch với editor (ảnh inline, `listItem` lẻ) | Thu hẹp grammar; SPA kiểm tra cả cây trước khi cho sửa |
| `marks` ở gốc tài liệu không bị kiểm | Từ chối |
| PNG giả chỉ có header | Kiểm tra phần kết thúc file theo định dạng, kích thước phải khác 0 |
| Replay upload đòi quyền khác lần đầu | Replay trả về cho chính người upload, nếu media chưa bị xoá |
| Mất dấu file khi dọn upload thua cuộc thất bại | Giữ intent cho tới khi xoá file thành công |
| File tạm và file `.partial` tồn đọng | `Storage::sweep`, chạy trong prune |
| Ghi local không bền khi mất điện | fsync file và thư mục |
| Tải file không giới hạn | Rate limit 600/phút/user |
| Tên file quá dài bị cắt ngầm; lỗi vượt dung lượng trả 422 | Tên > 255 ký tự → 422; vượt dung lượng ở bất kỳ phần nào → 413 |
| Default ở DB bỏ qua bước kiểm tra | Cấm default trên field media và rich text (kiểm lúc boot) |
| SPA: lưu khi upload dang dở; xoá item rồi upload xong làm nó hiện lại; ảnh trong editor mất key khi retry; alt/link đếm theo UTF-16; không sắp xếp lại được | Chặn lưu khi bận; append vào giá trị mới nhất; retry ảnh cùng key; đếm theo code point / byte; thêm nút di chuyển |

**Không sửa (đã ghi vào docs/ADR):**
- Không kiểm lại quyền lúc commit upload (giữ ranh giới "write đang chạy" từ 0.1).
- Tham chiếu media yêu cầu thêm `media.view_any`.
- S3: cần lifecycle rule để huỷ multipart upload dở; chưa probe bucket lúc boot.
- Upload phải xong trong một giờ.
