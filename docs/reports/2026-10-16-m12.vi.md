# Báo cáo M12: giao diện admin tiếng Anh và tiếng Việt

> Ngày: 16/10/2026 · trên `e1ce810` · chưa commit.
> Plan v2 đã chỉnh theo review của Codex (1 P1, 12 P2, 3 P3).

## 1. Người dùng thấy gì
- Trang **Account** có ô chọn ngôn ngữ (English / Tiếng Việt). Lựa chọn lưu vào tài khoản
  (`users.locale`), nên đổi máy vẫn giữ; đổi ngôn ngữ không đăng xuất ai.
- Chưa chọn thì theo ngôn ngữ trình duyệt, rồi tới `app.locale`. Trang đăng nhập cũng có ô chọn
  (nhớ trên máy đó).
- Toàn bộ giao diện được dịch: menu, danh sách, form, Tabs/KeyValue, media, rich text, trang
  Users/Roles, thông báo lỗi (cả lỗi server lẫn lỗi kiểm tra phía trình duyệt), ngày giờ theo locale.
- Đổi ngôn ngữ khi đang sửa form **không mất dữ liệu đang gõ**: chỉ nhãn đổi.

## 2. Cách làm
- **Nhãn của app** (resource, field, cột, filter, option, tab, action…): server dịch khi dựng schema,
  từ file `lang/vi.toml` kiểu Laravel (`"Post" = "Bài viết"`, bảng `[posts]` để dịch riêng một
  resource). File được nhúng vào binary. Framework có sẵn bản dịch cho tên field phổ biến và thư viện
  media. Lệnh `rustcms lang:missing vi` liệt kê nhãn còn thiếu.
- **Thông báo lỗi**: server vẫn trả tiếng Anh như cũ (API không đổi), thêm `issues` gồm mã + tham số
  cho từng lỗi; SPA dịch theo mã. Một test quét mã nguồn để không thông báo nào của framework thiếu mã.
  Lỗi do hook của app tự viết dùng `ctx.t("…")`.
- **SPA**: catalog `en.ts`/`vi.ts` (~400 chuỗi), kiểm tra đủ key, đủ placeholder, đủ dạng số nhiều;
  rule lint `i18n/no-literal-text` chặn chuỗi cứng mới.
- **Widget mở rộng**: có `ctx.locale`, `ctx.t`, `registerTranslations`; widget màu của demo đã dịch.

## 3. Sửa theo review plan của Codex
- **P1**: SPA từng nhận biết "ghi có thể đã áp dụng" bằng cách dò chữ tiếng Anh trong lỗi → dịch sẽ phá
  bảo vệ này. Nay dùng cờ riêng `outcomeUnknown`; test ở cả hai ngôn ngữ (reverse check: fail khi
  quay lại cách cũ).
- Bỏ cookie locale, bỏ việc viết lại response ở rìa admin (thiết kế đơn giản hơn, ít rủi ro hơn).
- Route `/locale` chỉ nhận session admin, CSRF + origin; khách, API token, origin lạ đều bị chặn (test).
- Test migration cũ dùng entity mới → đổi sang SQL theo schema cũ; thêm test nâng cấp 0.2 → 0.3.

## 4. Lỗi tìm thấy khi viết E2E
- Đổi ngôn ngữ: SPA chuyển sang key "vi" **trước** khi server lưu xong → lưu nhầm nhãn tiếng Anh vào
  cache. Sửa: lưu xong mới đổi, áp dụng locale của user ngay ở bước kiểm tra đăng nhập, và SPA gửi
  `Accept-Language` theo ngôn ngữ đang hiển thị.

## 5. Vòng Codex verify (0 P1, 6 P2, 3 P3) — đã sửa hết
- **P2** Trang Users/Roles nhận biết "người khác vừa sửa" bằng chữ tiếng Anh → hỏng khi dùng tiếng
  Việt. Nay dựa vào mã `stale` (`ApiError.hasIssue`).
- **P2** Tab B nhận ngôn ngữ mới từ tab A nhưng `/me` cũ trong cache kéo về ngôn ngữ cũ. Nay: bỏ qua
  `/me` lấy trước lựa chọn mới nhất, làm mới `/me` khi tab khác đổi, và SPA gửi `X-Rustcms-Locale` để
  server trả nhãn đúng ngôn ngữ tab đang hiển thị (cache luôn khớp key).
- **P2** Đổi ngôn ngữ làm mất lời giải thích của field bị khoá (JSON số lớn, KeyValue không hợp lệ):
  giữ lý do riêng và dịch lại.
- **P2** `lang:missing` tra nhóm menu theo phạm vi resource, trong khi menu tra toàn cục: nay tra đúng
  như lúc hiển thị, và liệt kê cả nhóm quyền.
- **P2** Nhóm quyền `users`/`roles`/`permissions` chưa dịch: hiển thị thành chữ ("Users") và có bản dịch.
- **P2** Lỗi đang hiển thị giữ ngôn ngữ cũ: `ApiError.message` đọc theo ngôn ngữ hiện tại; các trang lưu
  thông báo dạng "đọc khi hiển thị"; form gắn lại lỗi server và chạy lại kiểm tra phía trình duyệt khi đổi
  ngôn ngữ. (Khi làm, phát hiện truyền hàm vào `setState` bị React coi là updater — đã sửa ở mọi chỗ.)
- **P3** Tiêu đề tab trình duyệt đổi theo ngôn ngữ; `{{`/`}}` trong catalog thành dấu ngoặc; tham số rỗng
  (`filter[x][]`) vẫn giữ mã `unknown_operator`.
- Mỗi lỗi có test regression; reverse check: bỏ từng bản sửa thì test tương ứng fail.
