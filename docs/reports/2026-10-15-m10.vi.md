# Báo cáo M10 (0.2): MySQL là database thứ ba

> Ngày: 15/10/2026 · trên `b3fbf61` (M9) · chưa commit.
> Plan v2 đã chỉnh theo review của Codex (4 P1, 10 P2, 1 P3).
> Hỗ trợ **MySQL 8.4 LTS** (8.0 đã hết hạn hỗ trợ từ 4/2026). **MariaDB chưa hỗ trợ.**

## 1. Spike trước khi lập plan (MySQL 8.4, SeaORM 2.0.4 / sqlx-mysql 0.9)

| Phát hiện | Hệ quả cho thiết kế |
|---|---|
| `timestamp_with_time_zone()` thành `TIMESTAMP`: không nhận ngày sau 2038, mất phần lẻ giây | Instant dùng `DATETIME(6)` (UTC) qua helper |
| `OnConflict::do_nothing()` sinh `ON DUPLICATE KEY IGNORE` (sai cú pháp); upsert báo 1 dòng cả khi trùng | Claim idempotency trên MySQL: insert thường, bắt lỗi trùng khoá |
| Mặc định REPEATABLE READ; hook `after_connect` không chạy trên mọi connection của pool | `READ COMMITTED` đặt theo từng transaction (đã kiểm bằng hành vi) |
| Lỗi trùng khoá → `UniqueConstraintViolation` (1062); hết giờ chờ lock 1205, deadlock 1213 không được SeaORM phân loại | Map 1205/1213 → 409 `write_conflict` |
| `ESCAPE '\'` là lỗi cú pháp trên MySQL | Câu search riêng cho MySQL |

## 2. Đã làm

### Kết nối và kiểm tra lúc khởi động
- Feature `mysql` (bật mặc định trong `rustcms`).
- Connection luôn ở UTC và collation `utf8mb4_0900_bin` (phân biệt hoa thường, dấu
  và khoảng trắng cuối, giống PostgreSQL).
- `rustcms_core::db::check` chạy khi build app và trước `migrate`. Nếu database, cột
  chuỗi hay bảng nào không đúng (collation, InnoDB, `sql_mode` strict) thì từ chối
  khởi động, kèm câu SQL để sửa.

### Transaction và lock
- `begin_write` trên MySQL: `READ COMMITTED`, và đặt lại thời gian chờ lock 10 s
  cho mỗi transaction.
- `xact_lock(txn, name)` thay cho advisory lock chỉ có trên PostgreSQL:
  - PostgreSQL: vẫn dùng advisory lock;
  - MySQL: khoá một dòng của bảng `rustcms_locks` đã seed sẵn (2.049 tên), nên
    lúc khoá không bao giờ insert;
  - SQLite: không cần, vì write lock đã tuần tự hoá.
  - Dùng cho RBAC, lineage của session, quota idempotency.
- Quy tắc thứ tự lock: mỗi transaction lấy tối đa một named lock, và lấy trước mọi
  row lock.
- Row lock trên MySQL khoá từng dòng theo thứ tự key (InnoDB khoá khi quét, nên
  `ORDER BY` không đủ). Áp dụng cho `lock_rows` và lock media.

### Idempotency (sửa cho mọi DB)
- `acquire` lấy lock theo owner **trước**, rồi mới đọc receipt.
- Receipt hết hạn chỉ bị xoá khi vẫn còn hết hạn.
- Quota đếm sau khi đọc lại.
- Đóng hai race:
  - hai request cùng thay một receipt hết hạn;
  - một retry chạy đua với request vừa dùng key cuối của quota bị 429 oan.

### SQL khác biệt
- Search: dùng `CAST AS CHAR`; uuid dựng lại bằng `HEX` + `CONCAT`.
- Prune: dùng `DELETE … ORDER BY … LIMIT`.
- Map lỗi unique theo tên index của MySQL (kể cả index tự đặt theo tên cột).

### Migration
- Helper trong `rustcms::migration`: `create_table`, `create_index`, `add_column`,
  `drop_table`, `.instant()`, `.instant_now()`, `.local_date_time()`.
- DDL của PostgreSQL và SQLite giữ nguyên ý nghĩa.
- Mọi migration của framework chạy lại được sau khi lỗi giữa chừng (MySQL commit từng
  câu DDL): bảng, index, cột và seed đều bỏ qua phần đã có.
- Demo: trên MySQL, migration categories sửa bảng `posts` tại chỗ (không copy rồi
  đổi tên), nên không thể mất dữ liệu ghi xen vào giữa.
- Template `make:migration` và `.env.example` đã cập nhật.

### Media / rich text
- Kiểm tra "không có default" giờ dựa vào default thô của entity (trước đây bỏ sót
  default JSON).

### Test
- `db_test!` chạy trên 3 DB.
- MySQL: mỗi test một database, copy từ template đã migrate (bảng lấy từ
  `SHOW CREATE TABLE`, kèm dữ liệu).
- `RUSTCMS_TEST_REQUIRE` làm test fail nếu server bị bỏ qua (CI bật).
- docker compose và CI có MySQL 8.4.

## 3. Review Codex

### Review plan (4 P1, 10 P2, 1 P3) → plan v2

| Finding | Xử lý |
|---|---|
| Hai request cùng thay một receipt hết hạn (lỗi có sẵn, cả trên PostgreSQL) | `acquire` khoá theo owner trước, xoá có điều kiện |
| Chỉ kiểm collation mặc định của database là chưa đủ | Kiểm collation của từng cột chuỗi, engine của từng bảng |
| Demo rebuild bảng `posts` trên MySQL có thể mất dữ liệu ghi xen vào | Trên MySQL sửa bảng tại chỗ |
| Kiểm tra "không default" cho media/rich text bỏ sót default JSON | Dựa vào default thô |
| Retry chạy đua ở biên quota bị 429 | Đọc lại receipt sau khi khoá, rồi mới đếm |
| InnoDB, strict mode, UTC, NO PAD collation | Kiểm lúc khởi động, ép UTC, dùng `utf8mb4_0900_bin` |
| Thứ tự lock, deadlock do insert | Bảng lock seed sẵn, lock theo điểm, quy tắc thứ tự |
| `innodb_lock_wait_timeout` rò sang lần dùng connection sau | Mỗi write transaction đặt lại 10 s |
| Migration không chạy lại được sau lỗi giữa chừng | Helper bỏ qua phần đã có; test chạy lại mọi migration |
| Bảng tạo từ entity trong test vẫn dùng `TIMESTAMP` | `rustcms_testing::create_table` |
| Copy template thiếu kiểm tra | Kiểm `GET_LOCK`, cột ghi được, từ chối view/trigger |
| Chỉ test 8.4 nhưng ghi hỗ trợ 8.0.19+ | Thu hẹp còn 8.4 LTS |

### Verify (8 P2, 2 P3, không có P1) — đã sửa hết

| Finding | Xử lý |
|---|---|
| Pool tạo bên ngoài không bị ép UTC | `check` từ chối connection không ở UTC hoặc khác collation |
| Chỉ kiểm `sql_mode` của session | Kiểm cả global lẫn session |
| `NO_BACKSLASH_ESCAPES` làm mọi search trên MySQL lỗi | `check` từ chối mode này |

| Down của migration lineage không chạy lại được | Bỏ qua bước đã làm; helper `drop_column`; test chạy mọi down hai lần |
| Copy template bỏ sót cột có expression default | Lọc theo `generation_expression` |
| Lỗi retry chỉ nhận theo chuỗi tiếng Anh | Theo mã lỗi MySQL và SQLSTATE PostgreSQL; chuỗi chỉ là phương án cuối |
| Thời gian chờ claim kết thúc trước khi xoá/insert receipt | Giữ thời gian chờ ngắn suốt `acquire`, khôi phục khi kết thúc |
| Thiếu test: deadlock thật, so DDL, khoá ngoại của bản copy, rollback demo qua migration categories | Đã thêm cả bốn |

**Reverse check (fail-trước/pass-sau):**
- thứ tự `acquire` (hai test race, fail trên MySQL khi dùng thứ tự cũ);
- kiểm default thô cho rich text;
- down của lineage.

## 4. Kiểm chứng
- **Rust:** 632/632 trên SQLite + PostgreSQL + MySQL (`RUSTCMS_TEST_REQUIRE=postgres,mysql`,
  nên không backend nào được bỏ qua). Test mới:
  - `databases.rs`: kiểm setup MySQL (collation, engine, mode, UTC, backslash),
    named lock, instant sau 2038 và µs, chuỗi so sánh chính xác, timeout và
    deadlock → 409 kèm rollback toàn bộ, so DDL PostgreSQL/SQLite, khoá ngoại của
    bản copy;
  - `migrations.rs`: mọi up và down chạy lại được;
  - `idempotency.rs`: hai race.
  - Các test race ở `engine.rs` giờ thật sự bị chặn trên MySQL (dò bằng
    `performance_schema`), không còn chỉ `sleep`.
- **Khác:** fmt, clippy `-D warnings`, `just features` (có `mysql`), MSRV 1.94,
  `just doc`, `test-cli`, E2E 30/30. Contract, types và `cli.md` không đổi.
- **Ghi chú:** race thay receipt hết hạn chỉ tái hiện được trên MySQL khi dùng thứ tự
  cũ (trên PostgreSQL cửa sổ race quá hẹp với test hiện tại); bản sửa áp dụng cho mọi DB.
- **Chưa làm:**
  - MariaDB;
  - test với MySQL 8.0 (đã hết hạn hỗ trợ);
  - `cargo-deny` local (CI chạy). Không thêm dependency mới, chỉ bật thêm feature
    `sqlx-mysql` của SeaORM.

## 5. Lưu ý
- Database MySQL sẵn có phải chuyển sang `utf8mb4_0900_bin` trước khi chạy (app sẽ in
  câu SQL cần chạy).
- Không đụng SQLite demo local của anh. Nếu chạy demo thì `cargo run -- migrate`
  (migration mới `rustcms_locks`).
- docker compose có thêm service `mysql` (cổng 53306).
