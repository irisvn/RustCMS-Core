# Languages (i18n)

The admin panel speaks English and Vietnamese (`en`, `vi`). Only the interface
is translated: the content you manage stays in the language it was written in.

## Which language a user sees

1. The language the user chose on their account page (`users.locale`), if the
   deployment still offers it;
2. else the browser's language (`Accept-Language`), if offered;
3. else `app.locale`.

`GET /auth/me` returns that language and the panel switches to it. The panel
then sends the language it shows (`X-Rustcms-Locale`) with every request, and
labels come back in that language, so what a tab caches always matches what it
shows (another tab may have just switched).

```toml
# config/app.toml
locale = "en"              # default
locales = ["en", "vi"]     # what users may choose; a subset of what the panel ships
```

The choice is saved with `POST {admin}/api/auth/locale {"locale": "vi"}`
(`null`: follow the browser). It is not a credential change: sessions and tokens
stay valid. Before signing in, the login page offers the same choice, kept in
the browser.

## Translating your labels

Labels of resources, fields, columns, filters, options, tabs, sections, actions
and relations are English source strings. A catalog maps them to translations;
labels formed from column names (`published_at` → "Published at") are
translated the same way.

```toml
# lang/vi.toml
"Post" = "Bài viết"
"Posts" = "Bài viết"            # the plural: `.plural()` or "<label>s"
"Publish the selected posts?" = "Xuất bản các bài viết đã chọn?"

[posts]                          # this resource only
"Title" = "Tiêu đề bài viết"
```

```rust,ignore
AdminProvider::new().translations("vi", include_str!("../lang/vi.toml"))
```

- The catalog is compiled into the binary (no file to deploy).
- Lookup: the resource's table, then the global strings, then the framework's
  catalog (common field names and its own resources), else the source string.
- A translation must keep the `{placeholders}` of its source; `{{` and `}}`
  write braces. A malformed catalog or a language registered twice stops the
  boot. An empty translation (`"Title" = ""`) counts as missing.
- `rustcms lang:missing vi` lists the labels no catalog translates, as TOML to
  fill in, and exits with an error while any is missing (useful in CI). It reads
  the resource definitions; messages your hooks build at run time are not
  listed: translate them with `ctx.t("…")` (`ctx.t_in(slug, "…")`).
- Data, identifiers (slugs, field names, permission names) and role names are
  never translated. Permission groups get a translated `groupLabel`: a
  resource's plural label, or the group in words (`users` → "Users").

## Validation messages

Messages stay English on the wire (`errors`, `formErrors`, `message`), so API
clients see what they always did. Each message also has a stable code and its
parameters (text), which the panel translates:

```json
{"message": "The given data was invalid.", "code": "validation_failed",
 "errors": {"title": ["may not be longer than 200 characters"]},
 "issues": {"title": [{"code": "max_length", "params": {"max": "200"}}]},
 "formErrors": [], "formIssues": []}
```

A message that follows none of the framework's templates (your own text) has
the code `custom` and is shown as written. Conflicts (409) carry a `reason`
(`busy`, `upload_expired`, `receipt_expired`).

## Extensions

Widgets get the panel's language in `ctx.locale` and translate their own text
with `ctx.t("None")`, from catalogs they register while loading; `update` is
called when the language changes. Props are never translated.

```js
window.rustcms.registerTranslations("vi", { None: "Không màu" });
```

## The panel's own text

`admin-ui/src/i18n/en.ts` and `vi.ts` (every key, same placeholders: checked
by the compiler and the tests). A lint rule (`i18n/no-literal-text`) refuses
text written in place in the panel's code.
